# Commit Message Format Guide

## Overview
This document specifies the format standard for Git commit messages submitted to this repository.

## Commit Message Format

### Basic Structure
```
<type>: <subject>
```

## Type
Must be one of the following:

- **feat**: Add a new feature
- **fix**: Fix a bug
- **docs**: Documentation changes only
- **style**: Changes that do not affect code logic (whitespace, formatting, missing semicolons, etc.)
- **refactor**: Code refactoring that is neither a feature addition nor a bug fix
- **perf**: Performance optimization
- **test**: Add or modify tests
- **chore**: Update build scripts, dependencies, configuration files, etc.

## Subject
- Use imperative mood, present tense: "change" not "changed" or "changes"
- Do not capitalize the first letter
- Do not end with a period (.)
- Limit to 50 characters or less
- The first letter should be capitalized.
